# BorrowGlyph（借字）

BorrowGlyph 是一个面向设计场景的轻量汉字拼合辅助工具。

当字体缺少某个汉字时，输入目标字，BorrowGlyph 会根据汉字结构拆分其组成部件，并从其他汉字中寻找适合截取、拼合的候选字。它关注的不是文字学意义上的“标准拆字”，而是设计时“从哪个字里借这一块最省事”。

当前排序主要考虑：

1. **结构位置**：同一部件位于相同位置时优先；位置越接近目标字形，通常需要的缩放、拉伸越少。
2. **常用程度**：优先使用更常见、字体更可能收录的汉字。
3. **本字可用性**：部件本身就是一个字时，也可以直接作为 donor；但合适的同位 donor 仍可能优先于本字。
4. **部件深度**：优先使用更容易直接截取的部件。
5. **当前字体是否收录（可选）**：载入字体后，字体实际收录的候选优先。

例如「珣」拆为「⿰王旬」，可以分别寻找适合提供「王」和「旬」的字；如果一级部件本身没有合适 donor，BorrowGlyph 会继续向下拆分。对于 IDS 无法表达、但设计上明显更好用的拆法，也可以维护少量人工视觉特例。

## 当前功能

- 输入单个汉字，显示 IDS 结构和主要部件。
- 为每个部件列出 donor，并区分「同位 / 本字 / 近似位置 / 异位」。
- 一级部件没有合适 donor 时自动递归拆分。
- 支持少量人工视觉拆分特例；当前首个特例为「犮 → 友 + 丶」。
- 支持「不限 / 简体 / 繁体」候选范围切换；繁简共用字会保留在两边。
- 自动生成一组当前推荐方案，也可以手动点击候选字替换。
- 可选载入 TTF / OTF 字体；字体只在浏览器本地解析，不上传服务器。
- 载入字体后，字体实际收录的 donor 优先；未收录的候选只有在当前系统能够正常显示时才保留。
- 未载入字体时，会过滤当前浏览器只能显示成 tofu 方框的候选，避免无意义的「□」卡片。
- 完整结构数据作为独立静态资源加载，不打进主 JavaScript bundle。
- 纯前端静态网页，可部署到 GitHub Pages。

## 搜索逻辑

BorrowGlyph 的目标不是尽可能列出所有含某个部件的字，而是尽量找到“更适合直接拿来拼”的 donor。

一个典型优先级是：

**常见同位 donor → 可直接使用的本字 → 近似位置 donor → 异位 donor**

但这不是绝对硬规则。常用度、字体是否收录、是否需要明显变形都会影响最终排序。

如果正常 donor 不够好用，才会继续递归拆分；人工视觉拆分也只作为条件触发的补充，而不是无条件覆盖正常 donor。例如「髮」中的「犮」在缺少合适整块 donor 时可以走「友 + 丶」，但如果目标位置已经存在更合适的整块「犮」，仍优先直接截取。

## 本地运行

需要 Node.js 18+。

```bash
npm install
npm run dev
```

首次运行会从公开数据源生成 `public/data.json`。完整结构数据作为独立静态资源加载；仓库中保留了一份小型回退数据，因此刷新远程数据失败时仍可构建。

单独刷新数据：

```bash
npm run data
```

回归测试：

```bash
npm test
```

生产构建会先刷新数据并运行回归测试：

```bash
npm run build
```

当前回归测试覆盖了几类已经确认的重要行为，包括：

- 「爱」能够作为「友」的下部 donor。
- 独体「友」能够作为本字 donor。
- 「犮」能够保留来自不同结构位置的 donor。
- 「發」能够保留复合下部供递归拆分。
- 简体、繁体、繁简共用候选不会因为统一截断而互相挤掉。

## 数据来源

结构数据使用 [hfhchan/ids](https://github.com/hfhchan/ids) 的 IDS release（MIT License）。

常用度基础使用 [jaywcjlove/table-of-general-standard-chinese-characters](https://github.com/jaywcjlove/table-of-general-standard-chinese-characters) 整理的《通用规范汉字表》数据（MIT License）。一级、二级、三级字依次获得更高排序；繁体字会尽可能继承对应规范简体字的常用等级。

繁简属性也基于该项目提供的繁简转换数据，用于「不限 / 简体 / 繁体」候选筛选。

## 当前边界

BorrowGlyph 解决的是「**哪个字更适合借来切部件**」，不是自动完成最终字形设计。

IDS 描述的是结构关系，不能保证两个字在某一款字体里的局部轮廓完全一致；实际拼合仍可能需要缩放、位移和节点修整。对于 IDS 无法合理表达的视觉关系，也仍需要少量人工维护的设计特例。

系统字形显示能力取决于用户设备实际安装的字体；当前版本会过滤无法正常显示的 donor，而不是额外下载大字集 webfont。

## 下一步

### 上载字体字形预览

下一阶段优先完善**上载字体渲染**：将用户载入的字体作为候选字形的正式预览来源，让目标字、部件和 donor 更明确地按该字体实际字形显示，并清楚区分「上载字体命中」与「系统 fallback」。

当前版本已经完成字体本地解析、cmap 收录判断、候选优先级以及基础字体套用；下一步重点是把这部分整理成稳定、明确的设计预览体验。

## 部署

仓库包含 GitHub Pages Actions workflow。启用仓库的 Pages（Source 选择 **GitHub Actions**）后，推送到 `main` 会自动刷新数据、运行回归测试、构建并部署。
